# ComfyUI-Luori-Sunset

> 落日系列 · 提示词节点合集（Krea2 + Z-image）

把两个本地在用的提示词插件融合成一个：**一套词库、六个节点、零依赖**（no dependencies）。
原生控件收进折叠面板，画布更干净；画布搜索「落日」即可看到六个节点。

## 二、修复

### 1. 预设可能被整个清空（数据安全）

**现象**：预设文件一旦损坏（ComfyUI 写盘时崩溃、断电、磁盘满、手工改错一个逗号），再次保存任意一个预设，原有全部预设会被覆盖清空，且没有任何提示。

**原因**：读取失败时静默返回空字典 `{}`，保存时又以整份数据直接覆盖写入。

**修复**：
- 写入改为原子操作：先复制一份 `user_presets.bak.json`，再写临时文件、刷盘（`fsync`）、最后原子替换。中途断电不会留下半个文件。

### 2. 预设接口注册失败不再静默

**现象**：保存预设没反应，后端日志里却一个字都没有。

**原因**：`/luori/lr_presets` 的注册整段包在 `except Exception: pass` 里。

**修复**：捕获后输出警告日志 `[Sunset] LR 预设接口未注册：<原因>`，能直接定位是 aiohttp 版本、`PromptServer` 未就绪还是路由重复注册。

### 3. 种子 0 回传的是假种子（历史无法复现）

**现象**：手动把种子设为 0 抽到的卡，历史记录里显示“种子 0”；点击历史回填后又是随机，永远复现不了。

**原因**：种子为 0 时后端用系统熵随机，但回传给前端的种子字段仍写 0。

**修复**：种子为 0 时先生成一个真实的 64 位随机种子，再用它构建随机源，回传的就是实际使用的值。

实测：`seed=0` 连抽两次结果不同，两次回传的种子均非 0，用回传种子重跑结果 **100% 一致**。固定种子行为不变。

> 注意：修复前已存进工作流的历史记录里种子仍是 0，那批无法复现；新抽的卡开始正常。

## 三、优化

### 4. 词库缓存上限 24 → 64

当前全部词库加载完，缓存正好占满 24 条，已经踩在上限边缘。再加任何一个词库文件就会触发整表清空，下次抽卡需要重新解析约 60 MB 的 JSON（实测 `part-19` 173 ms、`part-hz1` 102 ms，合计约 0.5 秒）。

上限提高到 64 后，现有词库规模下不会再被清空。

## 四、升级后要做

1. **重启 ComfyUI** —— 所有 `.py` 改动必须重启才生效。
2. **浏览器强制刷新（Ctrl + F5）** —— 改了 `web/zimage_skin.js`，不刷新面板上的小标签仍是旧的。
3. 无需迁移数据。自定义预设、工作流、词库都不受影响。

## 特性

- **零依赖**：`dependencies = []`，只用 ComfyUI 自带环境，不需要 `pip install` 任何东西。
- **词库内置**：约 23 MB 词库随插件走，开箱可用；也可用环境变量指向你自己的词库。
- **组合矛盾率 0%**：原始词库 1200 轮抽卡有 8.3% 会抽出互相打架的组合
  （面料 × 款式、天气 × 室内），本插件内置兼容性过滤 → 实测 **0.0%**。
- **分类可扩展**：往 `data/zimage/extra/` 丢一个 `.json` 就多一个分类。
- **霓虹面板外观**：纯前端皮肤（`web/*.js`），不改任何节点逻辑；不想要外观删掉 `web/` 即可退化为原版控件。
- **原生控件默认隐藏**（`"hidden": True`）：加号收起、面板清爽，节点搜索预览卡片同步变干净。

## 用法

1. 搜索 `落日`，拖出需要的节点。
2. 节点底部面板点开分组，选分类 / 模式。
3. 节点输出 `prompt`（STRING）→ 接到 **CLIP Text Encode（CLIP 文本编码器）** 的 `text` 输入。
4. 连线后正常 Queue Prompt 即可。
